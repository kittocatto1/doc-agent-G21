| 3 OCR | Transcribe text from each detected region, respecting region type | Held-out labels: 15 hand-transcribed pages; 11/15 issues OCR'd as of submission, 4 remaining | Qwen2-VL-2B-Instruct | Zero-shot, region-kind-specific prompts, checkpointed every 25 regions | VLM chosen for region-type-aware prompting a traditional OCR engine can't do | Tested on single pages before scaling to full issues on Kaggle; validated with real word-level F1 against held-out labels (0.856 on 1981-05_p132; a second page, 1983-12_p019, scored 0.193 but was traced to a page-indexing offset in that document, not a genuine OCR failure) | Deferred to A4 | Deferred to A4 |
| 4 Index | Group OCR'd regions into retrievable chunks, embed them, and make them searchable, incrementally as more issues finish OCR | ~256-word chunks, 32-word overlap, grouped by doc_id, reading order preserved from layout; corpus is entirely English | BAAI/bge-small-en-v1.5 (384-dim); FAISS HNSW (m=32, ef_construction=200, ef_search=64) | store.py's build() checks for an existing index and appends new-issue vectors rather than rebuilding from scratch, supporting incremental addition as OCR completes issue-by-issue; duplicate doc_id detection prevents accidental re-indexing | Switched from Jina v5-text-small to BGE-small-en-v1.5: (1) limited Kaggle GPU time made Jina's 0.6B size unnecessary overhead; (2) Jina's multilingual support is wasted on an all-English corpus | Fixed a path-resolution bug in chunk.py (running from notebooks/ created a stray nested data/interim/ instead of resolving to the real project root); as of submission, the full chunk→embed→index pipeline had not yet completed a run on this machine due to local dependency setup (sentence-transformers) — real chunk/vector counts will be reported once the pipeline run completes, expected before A3 | FAISS HNSW index persisted as index.faiss + chunks_meta.json, loaded via store.load(); not committed to Git (data artifact, not source) | data/versioning.py — SHA256-hashes the corpus directory, records a version id + file count + timestamp per snapshot; especially relevant given the index builds incrementally across multiple partial runs |
| 5 Retrieval | Given a question, find the most relevant chunks quickly enough to meet our latency NFR | Indexed chunks from Row 4 | cross-encoder/ms-marco-MiniLM-L6-v2 for reranking | retrieve (k=10) -> widen if weak (k_step=10, k_max=40, weak_threshold=0.35) -> rerank -> abstain if still weak | Evidence-gated re-search balances recall against p95 ≤1.5s NFR | Planned for A3: unit-test widen-then-abstain on answerable vs. out-of-corpus questions | Deferred to A4 | Planned: log recall@k per query once live |

| 7 RL/RLVR | Optional bonus: improve extraction via checkable reward | Verifiable question set (exact-match gold) | PPO (rl: {algo: "ppo", train_policy: false}) | Reward = +1 on exact quote match | Not yet attempted (train_policy: false); genuinely bonus-tier, lowest priority vs. core NFR-driven build | Planned only if core A3 deliverables are solid with time remaining | Deferred to A4 | Planned: log reward per training step if attempted |
| 8 Serving | Make the agent reachable by a real user over the internet | N/A | serve: {batch: true} | Docker + API + UI; target: Hugging Face Spaces | Batching helps meet p95 ≤1.5s at higher query volume | Planned for A4: load-test under concurrent requests | HF Spaces — free, simple, matches walkthrough's suggested default | Planned: monitor error rate, abstention rate, latency once live |
